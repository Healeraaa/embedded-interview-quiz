# 嵌入式软件工程师秋招面试题库（MCU / STM32 / FreeRTOS 方向）

> 适用：应届生秋招、校招实习、偏 MCU/裸机/FreeRTOS 的嵌入式软件岗位。  
> 频率说明：★★★★★ 基本必问；★★★★ 高频；★★★ 常见；★★ 偶尔；★ 岗位相关时才问。  
> 学习原则：五星题要能脱稿讲清楚并应对追问；四星题要理解原理、能结合项目；三星题至少能给出定义和使用场景。

## 0. 自我介绍与项目总览

### 0.1 一分钟自我介绍怎么讲？【★★★★★】

建议结构：学校/专业 → 嵌入式技术栈 → 最有代表性的项目与个人职责 → 一个量化结果或难点 → 求职方向。

不要只报课程和工具名。示例骨架：

> 我主要做 MCU 嵌入式开发，熟悉 C、STM32 常用外设和 FreeRTOS。项目中负责过……，通过……解决了……问题，最终实现……。我希望应聘偏底层驱动、RTOS 和设备通信方向的嵌入式软件岗位。

### 0.2 介绍一个最能代表你的项目。【★★★★★】

必须覆盖：

- 项目要解决什么问题；
- 硬件平台、软件架构和通信方式；
- 你独立负责的部分，避免一直说“我们”；
- 最难的问题、定位过程、最终方案；
- 有数据的结果：周期、时延、丢包率、内存占用、功耗、稳定运行时间等；
- 如果重做一次会如何改进。

### 0.3 项目中为什么使用 FreeRTOS，而不是裸机？【★★★★★】

答题点：项目存在多个并发活动、不同实时性要求和阻塞等待；RTOS 能用任务划分、优先级调度、同步通信和软件定时器降低状态机复杂度。也要说明代价：RAM/ROM 和调度开销增加，存在竞态、死锁、优先级反转等问题。简单单功能系统未必需要 RTOS。

### 0.4 你的软件分层和模块边界如何设计？【★★★★】

建议回答：BSP/驱动层 → 服务或中间件层 → 业务应用层；上层尽量不直接操作寄存器；通过接口、回调、消息队列隔离模块；说明初始化顺序、数据流和错误处理方式。

### 0.5 项目最大的 Bug 是什么，如何定位？【★★★★★】

按“现象 → 复现条件 → 假设 → 证据 → 根因 → 修复 → 回归验证”回答。要说出工具：断点、Watch、串口日志、逻辑分析仪、示波器、HardFault 栈回溯、map 文件等。

## 1. C 语言基础

### 1.1 `static` 有哪些作用？【★★★★★】

- 修饰局部变量：静态存储期，只初始化一次，作用域仍在函数内；
- 修饰全局变量：限制为当前源文件内部链接；
- 修饰函数：限制函数只能在当前源文件使用。

追问：静态局部变量通常位于 `.data` 或 `.bss`，不在普通栈帧中。

### 1.2 `const` 的作用是什么？`const` 变量一定在只读区吗？【★★★★★】

`const` 表示通过该标识符不能修改对象，有助于接口约束和编译检查；存放位置取决于对象类型、链接方式和链接脚本，不应简单等同于“必然在 Flash/只读区”。还要会区分：

```c
const int *p;        // 指向常量的指针：不能通过 p 改值
int * const p2 = 0; // 常量指针：p2 本身不能改指向
const int * const p3 = 0;
```

### 1.3 `volatile` 有什么作用？什么时候必须用？【★★★★★】

告诉编译器每次都要按抽象机规则访问该对象，不能把值长期缓存或消除必要访问。典型场景：硬件寄存器、被 ISR 和主程序共同访问的标志、被其他执行上下文异步改变的数据。

关键陷阱：`volatile` 不保证原子性，不提供互斥，不等价于内存屏障，也不能单独解决多线程竞态。

### 1.4 `sizeof` 和 `strlen` 有什么区别？【★★★★★】

`sizeof` 是运算符，求对象/类型占用字节数，多数情况下编译期确定；`strlen` 是库函数，遍历到字符串的 `\0`，返回字符数且不包含终止符。数组传参后会退化为指针，函数内 `sizeof(param)` 得到的是指针大小。

### 1.5 数组与指针有什么区别？数组什么时候退化为指针？【★★★★★】

数组是连续对象集合，数组名不是可修改左值；在大多数表达式中转换为首元素指针，但作为 `sizeof`、一元 `&` 的操作数以及字符串字面量初始化数组等场景不会发生该转换。

### 1.6 指针数组与数组指针有什么区别？【★★★★】

```c
int *a[10];    // 含 10 个 int* 的数组
int (*p)[10];  // 指向“含 10 个 int 的数组”的指针
```

### 1.7 函数指针有什么用？【★★★★】

典型用途：回调函数、中断向量、状态机、驱动接口表、协议解析分发表。要会声明和调用，并说明回调的参数、生命周期和执行上下文约束。

### 1.8 结构体为什么会有内存对齐？如何计算大小？【★★★★★】

成员按各自对齐要求放置，结构体整体大小通常补齐为最大对齐值的整数倍，以提高访问效率并满足处理器要求。要会手算含 `char`、`short`、`int`、指针、数组和嵌套结构体的大小。

追问：`#pragma pack` 或 packed 属性可减小空间，但可能造成非对齐访问、性能下降甚至硬件异常；协议帧解析不应随意把缓冲区强转为 packed 结构体。

### 1.9 大端和小端是什么？如何判断？【★★★★】

大端：高有效字节放低地址；小端：低有效字节放低地址。网络字节序通常为大端。可用 `uint16_t x = 1` 后读取最低地址字节判断，但实际项目优先使用明确的字节编解码函数。

### 1.10 宏和内联函数有什么区别？【★★★★】

宏是预处理文本替换，无类型检查，参数可能被重复求值；内联函数有类型和作用域规则，是否真正内联由编译器决定。宏参数与整体表达式必须加括号，避免优先级问题。

### 1.11 写一个安全的 `MAX` 宏要注意什么？【★★★】

普通宏即使加括号也会重复计算参数，例如 `MAX(i++, j++)`。在标准 C 中更推荐类型明确的 `static inline` 函数；若用编译器扩展，需要明确可移植性。

### 1.12 `typedef` 与 `#define` 的区别？【★★★】

`typedef` 由编译器处理并遵循类型系统，可正确表达指针别名；宏只是预处理替换。经典陷阱：`#define P int*` 后 `P a,b;` 只有 `a` 是指针，而 `typedef int* P; P a,b;` 两者都是指针。

### 1.13 `extern` 的作用是什么？头文件中如何组织声明？【★★★★】

`extern` 声明对象或函数在其他翻译单元定义。头文件放声明，某一个 `.c` 文件放唯一的定义；使用 include guard，避免在头文件中定义普通全局变量。

### 1.14 `inline` 的含义是什么？【★★】

它主要是对编译器的优化建议，还涉及 C 语言链接语义；不保证消除函数调用。嵌入式项目常用 `static inline` 在头文件中定义短小、频繁调用的函数。

### 1.15 `switch`、状态机和大量 `if-else` 如何取舍？【★★★★】

状态明显、转移清晰时使用显式有限状态机，便于处理超时、异常和事件；不要用阻塞延时把所有流程串死。回答时最好结合通信协议或设备控制项目画出状态转移。

### 1.16 有符号与无符号混合运算有什么风险？【★★★★】

整型提升和通常算术转换可能把负数转为很大的无符号数；长度、下标比较中特别常见。还要注意溢出：无符号溢出按模运算，有符号溢出属于未定义行为。

### 1.17 `memcpy` 与 `memmove` 有什么区别？【★★★★】

`memcpy` 要求源和目标不重叠；`memmove` 支持重叠区域，通常根据地址决定复制方向。两者都不负责字符串终止或对象深拷贝。

### 1.18 `strcpy`、`sprintf` 有什么风险？【★★★★】

可能发生缓冲区溢出。使用有边界的接口并正确检查返回值，如 `snprintf`；`strncpy` 也可能不补 `\0`，不能机械替换。嵌入式还要考虑格式化函数的栈和代码体积开销。

### 1.19 什么是未定义行为？举例。【★★★】

例如越界访问、使用已释放内存、空指针解引用、有符号溢出、修改字符串字面量、未加同步的数据竞争等。编译器可以基于“未定义行为不会发生”进行激进优化。

### 1.20 如何实现环形缓冲区？【★★★★★】

核心字段：缓冲区、读索引、写索引，可选计数；要定义空/满判定（牺牲一个槽位或额外计数/标志）。考虑索引回绕、并发访问、DMA 写入、覆盖策略。若容量为 2 的幂，可在满足无符号条件下用掩码优化取模。

### 1.21 如何写一个位操作：置位、清零、翻转、读取？【★★★★★】

```c
x |=  (1u << n);       // 置位
x &= ~(1u << n);       // 清零
x ^=  (1u << n);       // 翻转
b = (x >> n) & 1u;     // 读取
```

注意位宽、移位越界、符号扩展和 `1u` 的类型。

### 1.22 如何判断一个数是否是 2 的幂？【★★★】

在无符号且 `x != 0` 时：`(x & (x - 1u)) == 0u`。

### 1.23 递归为什么通常不适合资源受限 MCU？【★★★】

栈消耗难界定，深度失控会栈溢出，执行时间也难分析。能改为迭代或显式栈时通常更适合实时系统。

### 1.24 浮点运算在 MCU 上有什么注意事项？【★★★】

确认是否有 FPU、ABI 和编译选项是否匹配；中断/任务切换是否需要保存浮点上下文；格式化输出浮点可能显著增大固件；实时路径可考虑定点数，但要分析范围、精度和溢出。

## 2. 指针、内存与编译链接

### 2.1 MCU 程序常见内存段有哪些？【★★★★★】

- `.text`：代码和只读内容，通常在 Flash；
- `.rodata`：只读常量，通常在 Flash；
- `.data`：有非零初值的全局/静态变量，初值在 Flash，启动时复制到 RAM；
- `.bss`：零初始化或未显式初始化的全局/静态变量，启动时清零；
- heap：动态分配区；
- stack：函数栈帧、局部变量、保存现场等。

### 2.2 栈和堆有什么区别？【★★★★★】

栈通常按调用自动分配回收，速度快但容量有限；堆由分配器管理，生命周期灵活，但可能碎片化、失败且执行时间不确定。RTOS 中还要区分每个任务栈与 FreeRTOS heap。

### 2.3 野指针、悬空指针和内存泄漏分别是什么？【★★★★★】

野指针：未正确初始化、指向未知地址；悬空指针：所指对象生命周期已结束；内存泄漏：分配的内存失去可达引用而无法释放。措施包括初始化为 `NULL`、明确所有权、释放后置空、减少动态分配、静态分析。

### 2.4 为什么嵌入式项目常避免运行期 `malloc/free`？【★★★★】

可能碎片化、分配耗时不确定、失败路径难覆盖、线程安全和长期稳定性风险。并非绝对不能用，可在初始化阶段统一分配、使用内存池/固定块分配、监控剩余空间并禁止在关键实时路径分配。

### 2.5 什么是内存碎片？【★★★★】

外部碎片：总空闲足够但缺少足够大的连续块；内部碎片：分配块内部因对齐或固定粒度产生浪费。固定块内存池可减少外部碎片并提供确定时间。

### 2.6 深拷贝和浅拷贝有什么区别？【★★★】

浅拷贝只复制指针值，多个对象共享底层资源；深拷贝复制其拥有的数据。必须明确资源所有权、释放责任以及并发修改规则。

### 2.7 空指针与 `void *` 是什么？【★★★】

空指针不指向有效对象；`void *` 是通用对象指针，可与其他对象指针转换，但解引用前必须转成具体类型。函数指针与对象指针不应默认可移植地互转。

### 2.8 指针越界为什么危险？【★★★★★】

可能破坏栈、控制块、函数返回地址或外设映射区，导致延迟性随机故障。防护：边界检查、长度与缓冲区绑定、编译器告警、栈保护、MPU、静态分析和压力测试。

### 2.9 从源文件到可执行固件经历哪些步骤？【★★★★】

预处理 → 编译 → 汇编 → 链接 → 生成 ELF，再转换为 bin/hex。链接器负责符号解析和段布局；启动文件负责复位入口、栈、向量表和运行时初始化。

### 2.10 map 文件有什么用？【★★★★】

查看段地址与大小、符号所在位置、RAM/Flash 占用、谁引入了大对象或库函数、栈堆配置等，是分析内存超限和固件体积的重要依据。

### 2.11 链接脚本做什么？【★★★】

描述存储区域和各段放置规则，定义入口和相关符号。Bootloader、App 分区、向量表偏移、RAM 函数和特殊保留区都常通过链接脚本实现。

### 2.12 什么是内存映射 I/O？【★★★★】

外设寄存器被映射到处理器地址空间，通过指针读写。寄存器定义通常需要 `volatile`，还要遵循位宽、访问顺序、读改写副作用和硬件手册要求。

### 2.13 如何估算和检测栈使用量？【★★★★★】

静态看调用深度、局部大对象、中断嵌套和库函数；运行时可用填充水位法、FreeRTOS `uxTaskGetStackHighWaterMark()`、栈溢出钩子。注意高水位表示历史最小剩余量而非当前使用量，且要留足最坏情况余量。

### 2.14 为什么不要在栈上放很大的数组？【★★★★】

任务栈通常很小，大数组会快速耗尽并可能破坏相邻内存。可改用静态缓冲区、受控内存池或共享缓冲区，但同时处理好可重入性和并发访问。

### 2.15 什么是原子操作？【★★★★】

从其他执行上下文观察时不可分割的操作。某个宽度的对齐读写是否原子取决于架构；`i++` 通常是读-改-写，不是原子。可使用临界区、架构原子指令或 RTOS 同步原语。

## 3. MCU、启动、中断与异常

### 3.1 MCU 上电后程序如何运行到 `main()`？【★★★★★】

处理器从向量表取得初始 MSP 和 Reset_Handler；复位处理函数完成时钟/底层初始化，复制 `.data`、清零 `.bss`，可能执行 C/C++ 运行时初始化，然后调用 `main()`。具体顺序以启动文件和工具链为准。

### 3.2 中断发生时硬件和软件做了什么？【★★★★★】

以 Cortex-M 为例：完成当前指令后，硬件自动压入部分寄存器并根据向量表进入 ISR；ISR 处理并清除中断源，异常返回时恢复现场。还应说明优先级、屏蔽、嵌套和尾链等概念。

### 3.3 中断服务函数中应避免做什么？【★★★★★】

避免长时间执行、阻塞等待、普通互斥锁、动态内存、复杂格式化打印和不可重入函数。ISR 应快速获取/清除事件，把后续工作通过标志、队列、任务通知等交给任务。

### 3.4 为什么进入中断后要清中断标志？何时清？【★★★★★】

不清可能退出后立即再次进入。清除时机和方式必须看芯片手册：有些写 1 清除，有些读特定寄存器后再读数据清除，有些建议先清再处理以避免漏事件；不能套用统一规则。

### 3.5 中断优先级数值越大优先级越高吗？【★★★★★】

在 Cortex-M NVIC 中通常优先级数值越小、逻辑优先级越高。需区分抢占优先级与子优先级，并说明优先级位数由芯片实现。

### 3.6 FreeRTOS 中断优先级为什么容易配置错？【★★★★★】

能调用 `...FromISR()` API 的中断，其优先级必须处在 FreeRTOS 允许管理的范围内；高于该阈值的超高优先级中断不能调用这些 API。要分清 `configMAX_SYSCALL_INTERRUPT_PRIORITY`、库优先级数值与 NVIC 左移后的寄存器表示。

### 3.7 ISR 和任务共享变量如何保护？【★★★★★】

先判断数据访问是否原子；简单事件优先用任务通知、队列、流缓冲区；短小共享状态可用适合 ISR 的临界区或短暂屏蔽中断。仅加 `volatile` 不够。不可在 ISR 使用会阻塞的普通 API。

### 3.8 什么是中断延迟和响应时间？【★★★★】

中断延迟是从事件发生到开始执行 ISR 的时间，受关中断区间、更高优先级 ISR、当前指令等影响；完整响应时间还包括 ISR 和后续任务被调度执行的时间。优化要控制临界区和 ISR 最坏执行时间。

### 3.9 轮询和中断如何选择？【★★★★★】

低频、异步、需及时响应的事件通常适合中断；极高频或处理成本很低时，中断风暴可能反而更差，可采用轮询、DMA 或批处理。简单、固定周期读取也可在任务中轮询。选择依据是实时性、CPU 占用和复杂度。

### 3.10 什么是 HardFault？如何定位？【★★★★★】

可能来自非法地址、未对齐、栈溢出、错误函数指针、除零或总线错误等。定位步骤：保存现场；判断使用 MSP/PSP；读取堆栈中的 PC/LR；查看 CFSR、HFSR、BFAR、MMFAR；结合 map/反汇编定位源码；检查栈水位和最近内存写入。

### 3.11 看门狗有什么作用？独立看门狗和窗口看门狗区别？【★★★★】

看门狗用于系统失控时复位。独立看门狗通常使用独立低速时钟；窗口看门狗要求在指定窗口内喂狗，过早和过晚都可能触发。喂狗应代表系统健康，不能由一个永远运行的高优先级任务无条件喂。

### 3.12 SysTick 有什么作用？【★★★★】

常作为系统节拍来源，为 HAL 延时或 RTOS tick 提供时间基准。使用 RTOS 后要理解 HAL tick 与 RTOS tick 的优先级、时间源和冲突问题。

### 3.13 什么是临界区？为什么越短越好？【★★★★★】

临界区是访问共享资源、不能被并发打断的代码区。实现可能是关调度或屏蔽一定范围中断；过长会增加中断延迟和任务响应抖动，破坏实时性。

### 3.14 中断嵌套的条件是什么？【★★★】

硬件支持嵌套、优先级分组和屏蔽状态允许，且新中断具有更高抢占优先级。设计时要考虑共享资源、栈最坏占用和执行时间。

### 3.15 Cortex-M 的 MSP 和 PSP 有什么区别？【★★★】

MSP 常用于复位后和异常处理；PSP 可用于线程模式，FreeRTOS 通常让任务使用各自基于 PSP 的栈，而异常进入后使用 MSP。具体实现看端口层。

## 4. I²C

### 4.1 I²C 的基本信号和特点是什么？【★★★★★】

两根线 SDA/SCL、同步、半双工、多主多从、开漏输出，需要上拉电阻。空闲时两线为高；设备通过地址识别。

### 4.2 I²C 的起始和停止条件是什么？【★★★★★】

SCL 为高时 SDA 从高到低是 START；SCL 为高时 SDA 从低到高是 STOP。数据位通常在 SCL 高电平期间保持稳定。

### 4.3 ACK/NACK 如何工作？【★★★★★】

每传 8 位后，第 9 个时钟由接收方应答。拉低 SDA 表示 ACK，保持高表示 NACK。主机读最后一个字节时通常发送 NACK，再产生 STOP 或重复起始。

### 4.4 7 位地址和 8 位“地址”为什么容易混淆？【★★★★★】

总线传输的首字节通常由 7 位从机地址左移一位再加 R/W 位组成。有些数据手册给的是已左移的读写地址。驱动 API 需要哪一种必须看文档，不能凭习惯。

### 4.5 什么是重复起始条件？【★★★★】

主机不释放总线，直接再次发 START，常用于“先写寄存器地址、再读数据”，避免中间被其他主机占用，并保持一次原子事务。

### 4.6 I²C 为什么需要上拉？阻值如何选择？【★★★★】

开漏器件只能主动拉低，释放后靠上拉变高。阻值要在灌电流能力和 RC 上升时间之间权衡；线长、电容、速率越高，通常需要更强上拉，但不能超过器件低电平电流规格。

### 4.7 I²C 总线被拉死怎么办？【★★★★】

先判断 SDA/SCL 谁被拉低；复位控制器并重配 GPIO；若从机卡在传输中，可按器件建议手动产生若干 SCL 脉冲（常见为 9 个）并生成 STOP；必要时复位或断电从机。必须加入超时，不能永久等待 BUSY。

### 4.8 什么是时钟拉伸和多主仲裁？【★★★】

从机可拉低 SCL 延迟主机，称时钟拉伸；多主同时发送时，通过监测 SDA 实现逐位仲裁，发送高却读到低的一方退出。确认 MCU 外设和驱动是否支持。

### 4.9 I²C 通信错误如何调试？【★★★★★】

检查供电、共地、上拉、地址、速率与时序；用逻辑分析仪看 START、地址、ACK、寄存器地址和数据；区分地址 NACK、数据 NACK、超时、仲裁丢失和总线错误；降低频率并交叉验证设备手册。

### 4.10 硬件 I²C 与软件模拟 I²C 如何选择？【★★★】

硬件 I²C 占 CPU 少、可配合 DMA/中断，但外设状态机和异常恢复可能复杂；软件模拟灵活、便于特殊时序和换引脚，但占 CPU、实时性依赖中断和延时准确性。

## 5. SPI

### 5.1 SPI 的信号和特点是什么？【★★★★★】

常见四线：SCLK、MOSI、MISO、CS；同步、全双工、主从式、无统一地址和应答机制，速度通常高于 I²C。多个从机一般各用独立 CS，或采用菊链。

### 5.2 CPOL 和 CPHA 是什么？四种模式如何理解？【★★★★★】

CPOL 决定时钟空闲电平；CPHA 决定在第一个还是第二个有效边沿采样。主从模式必须一致。不要只背编号，要能根据器件时序图判断在哪个边沿改变和采样数据。

### 5.3 SPI 为什么“发送才能接收”？【★★★★★】

SPI 每个时钟边沿同时移出和移入一位；主机要提供时钟，因此读取时也要发送 dummy 数据。写操作期间接收到的数据可能无意义，但接收寄存器仍需按硬件要求处理。

### 5.4 SPI 没有 ACK，如何保证通信可靠？【★★★★】

由上层协议或器件机制保证：状态寄存器、校验/CRC、帧头帧长、序号、超时重试、读回校验和错误引脚等。

### 5.5 CS 时序有什么常见坑？【★★★★】

器件常规定 CS 建立/保持时间、字节间是否允许抬高、一次事务包含多少字节。使用 DMA 时不能在 DMA 尚未完成就抬高 CS，还要等待 SPI 移位寄存器真正空闲，而不只是 DMA 完成。

### 5.6 SPI 收到的数据整体错一位或全是 `0xFF/0x00` 怎么查？【★★★★★】

检查 CPOL/CPHA、位序、数据宽度、CS、MISO 是否浮空、主从是否共地、频率是否过高；逻辑分析仪对照数据手册时序。全 `0xFF` 常见于线路被上拉/从机未驱动，全 `0x00` 可能是被拉低或器件未工作，但要以波形为准。

### 5.7 SPI、I²C、UART 如何选型？【★★★★★】

从吞吐量、引脚数量、距离、设备数量、全双工需求、错误检测、布线和软件复杂度权衡。不要只回答“SPI 快、I²C 省线、UART 简单”，要结合实际设备和速率。

### 5.8 QSPI/OSPI 是什么？【★★】

通过多条数据线提高吞吐，可连接外部 Flash，并可能支持内存映射执行 XIP。需考虑缓存、一致性、擦写期间不可读和时序校准。

## 6. UART 与 CAN

### 6.1 UART 一帧包含什么？【★★★★★】

空闲电平、起始位、数据位、可选校验位、停止位。通信双方必须匹配波特率、数据位、校验和停止位。

### 6.2 波特率和比特率有什么区别？【★★★★】

波特率是每秒符号数，比特率是每秒比特数；二进制 UART 中通常数值相同。计算有效吞吐时要把起始、校验和停止位开销算进去。

### 6.3 UART 为什么会出现乱码？【★★★★★】

波特率或帧格式不匹配、时钟误差、地线/电平标准错误、线路干扰、缓冲区溢出、数据解析边界错误、并发打印交叉等。先看物理波形和原始字节，再看协议解析。

### 6.4 TTL UART、RS-232、RS-485 有什么区别？【★★★★】

UART 是数据帧/控制器概念；TTL/CMOS UART 使用单端逻辑电平；RS-232 是不同电平和极性标准；RS-485 使用差分信号，适合较远距离、多节点，常见半双工并需要方向控制和终端匹配。

### 6.5 UART 不定长数据怎么接收？【★★★★★】

常见方案：逐字节中断 + 环形缓冲；DMA 循环接收 + 空闲线 IDLE；协议层用帧头、长度、超时、帧尾或转义确定边界。必须处理半包、粘包、噪声、溢出和重新同步。

### 6.6 UART DMA + IDLE 的处理流程是什么？【★★★★★】

DMA 接收数据，IDLE 或 DMA 半满/满事件触发处理；通过 DMA 剩余计数计算新数据区间，将数据写入环形缓冲或通知解析任务；清标志并继续接收。要考虑事件竞争、缓冲回绕、缓存一致性及处理不及时导致覆盖。

### 6.7 如何设计健壮的串口协议？【★★★★】

帧头/同步字、版本、命令、长度、序号、负载、CRC；规定字节序、最大长度、超时和异常恢复；解析器先做长度与边界检查，再校验；遇错能重新寻找同步点。

### 6.8 校验和与 CRC 有什么区别？【★★★★】

简单校验和成本低但检错能力有限；CRC 对突发错误等具有更强检出能力。双方必须一致约定多项式、初值、输入/输出反射、结果异或和字节顺序。

### 6.9 CAN 的主要特点是什么？【★★★★★】

多主、广播、差分物理层、基于标识符的优先级仲裁、强错误检测与自动重发。经典 CAN 数据场最多 8 字节；CAN FD 支持更长数据和数据阶段更高速率。

### 6.10 CAN 是按节点地址通信吗？【★★★★★】

不是传统点对点地址模式。报文 ID 描述消息含义并参与仲裁，所有节点可接收，再由硬件过滤器和软件决定是否处理。

### 6.11 CAN 仲裁为什么不会破坏报文？【★★★★★】

显性位覆盖隐性位。节点边发送边监测总线；发送隐性却读到显性的节点失去仲裁并停止发送，胜出节点的报文保持完整。ID 数值越小通常优先级越高。

### 6.12 CAN 总线为什么需要 120Ω 终端电阻？【★★★★】

在线缆两端匹配特性阻抗，减少信号反射。断电测 CAN_H 与 CAN_L 间通常约 60Ω，表示两只 120Ω 并联，但还应结合拓扑和设备内部终端判断。

### 6.13 CAN 的错误状态有哪些？【★★★】

节点依据发送/接收错误计数进入 Error Active、Error Passive，严重时进入 Bus Off。工程上要设计 Bus Off 恢复、告警和故障记录，不能只自动重启掩盖问题。

### 6.14 CAN 收不到数据如何排查？【★★★★★】

检查收发器供电/使能、共地、终端电阻、CAN_H/L、波特率和采样点、过滤器、ID 类型、引脚复用和中断；用示波器/分析仪确认是否有帧和错误帧；查看控制器错误计数与状态。

### 6.15 CAN 标准帧和扩展帧区别？【★★★】

标准 ID 为 11 位，扩展 ID 为 29 位；仲裁字段与开销不同。配置过滤器和发送邮箱时要同时确认 IDE、RTR 等字段。

## 7. FreeRTOS 基础与任务管理

### 7.1 什么是实时系统？硬实时和软实时区别？【★★★★★】

实时性强调在截止时间内完成，而不只是平均速度快。硬实时错过截止时间不可接受；软实时偶尔超时会降低质量但通常不造成灾难。分析要关注最坏执行时间和最坏响应时间。

### 7.2 FreeRTOS 任务有哪些主要状态？【★★★★★】

Running、Ready、Blocked、Suspended；一些资料还单列 Deleted/终止等待回收。Blocked 是在等待时间或事件，时间/事件满足后回 Ready；Suspended 不会因超时自动恢复。

### 7.3 FreeRTOS 如何进行任务调度？【★★★★★】

固定优先级抢占调度为常见配置：最高优先级的 Ready 任务运行；同优先级任务可按时间片轮转，具体由配置决定。阻塞、ISR 唤醒更高优先级任务或 tick 到来都可能触发切换。

### 7.4 任务切换保存了什么？【★★★★】

保存当前任务上下文并恢复下一个任务上下文，包括需要保留的 CPU 寄存器、栈指针及端口相关状态。Cortex-M 端口通常利用 PendSV；部分寄存器由异常机制自动保存，部分由端口代码保存。

### 7.5 FreeRTOS 为什么常用 SysTick、PendSV 和 SVC？【★★★★】

SysTick 提供节拍；PendSV 设为很低优先级，延后执行上下文切换；SVC 可用于启动首个任务或特权服务。要结合具体 FreeRTOS 端口回答。

### 7.6 抢占式调度与协作式调度区别？【★★★★】

抢占式可在更高优先级任务就绪时立即切换，响应快但并发复杂；协作式依赖任务主动让出 CPU，简单但一个任务不让出就会拖住系统。

### 7.7 `vTaskDelay()` 与 `vTaskDelayUntil()` 区别？【★★★★★】

`vTaskDelay()` 是从调用时刻开始相对延时，循环执行时间会累积造成漂移；`vTaskDelayUntil()` 以固定基准周期唤醒，更适合周期任务。任务唤醒只是变为 Ready，何时真正运行还受优先级影响。

### 7.8 为什么不能用忙等延时代替任务阻塞？【★★★★★】

忙等持续占用 CPU，低优先级任务无法运行，也不利于低功耗。任务等待事件或时间时应进入 Blocked，让调度器运行其他任务或进入空闲/低功耗。

### 7.9 如何划分任务？任务越多越好吗？【★★★★★】

按独立并发活动、不同实时性和清晰职责划分；过少会形成巨型任务和复杂状态机，过多会增加栈、切换、同步和调试成本。避免把每个小函数都做成任务。

### 7.10 如何设置任务优先级？【★★★★★】

依据截止时间、响应要求和阻塞关系，而不是“功能重要性”。高优先级任务应短、常阻塞；CPU 密集任务不应长期占最高优先级。验证最坏负载下所有任务都能满足时序。

### 7.11 高优先级任务一直运行会怎样？【★★★★★】

低优先级任务会饥饿，包括 Idle 任务；若删除任务依赖 Idle 回收资源，也可能无法回收。高优先级任务必须在无事时阻塞、延时或等待通知。

### 7.12 Idle 任务做什么？【★★★★】

保证始终有任务可运行，回收已删除任务的内存；可执行 Idle Hook，但钩子不能阻塞。Tickless Idle 等低功耗机制也常基于空闲时间。

### 7.13 FreeRTOS tick 越高越好吗？【★★★★】

高 tick 提高时间粒度，但增加周期中断和调度开销、功耗；低 tick 减少开销但延时粒度变粗。tick 不等于任务执行频率，也不能保证绝对精准的微秒级定时。

### 7.14 `portTICK_PERIOD_MS` 和 `pdMS_TO_TICKS()` 有何注意？【★★★】

优先用 `pdMS_TO_TICKS()` 转换；注意整数截断、超长时间溢出和 0 tick 结果。超时逻辑还要正确处理 tick 计数回绕，优先使用 FreeRTOS 提供的阻塞/超时接口。

### 7.15 动态创建与静态创建任务如何选？【★★★★】

动态创建方便，但依赖 heap；静态创建由调用者提供 TCB 和栈，内存可控、适合高可靠场景。无论哪种都要检查创建结果和栈水位。

### 7.16 删除任务后内存何时释放？【★★★】

动态创建任务被删除后，相关内存通常由 Idle 任务清理，因此 Idle 必须获得运行机会。任务持有的其他资源不会被内核自动正确归还，删除前要有明确清理协议。

### 7.17 FreeRTOS 的 `heap_1` 到 `heap_5` 有何区别？【★★★★】

- `heap_1`：只分配不释放，简单确定；
- `heap_2`：可释放但不合并相邻空闲块，易碎片；
- `heap_3`：封装标准 `malloc/free`，加调度保护；
- `heap_4`：可释放并合并相邻空闲块，最常见；
- `heap_5`：类似 heap_4，支持多个不连续内存区域。

### 7.18 如何检查 FreeRTOS 内存是否足够？【★★★★】

检查创建 API 返回值、`xPortGetFreeHeapSize()` 和历史最小剩余堆、每个任务栈高水位；启用 malloc failed hook 和 stack overflow hook；在最坏业务负载、最长运行和通信突发下测试。

### 7.19 软件定时器回调在哪执行？能阻塞吗？【★★★★★】

在 Timer Service/Daemon Task 上下文执行，不是硬件 ISR。回调应短小且不能长时间阻塞，否则会延迟其他定时器命令与回调。其队列长度、任务优先级和栈大小需要配置。

### 7.20 软件定时器与任务延时如何选？【★★★★】

少量短小的周期/一次性回调适合软件定时器；需要阻塞、复杂处理或独立优先级的功能适合任务。高精度硬实时定时通常依赖硬件定时器，而非 RTOS tick。

### 7.21 什么是 Tickless Idle？【★★★】

系统预计一段时间无任务需要运行时抑制周期 tick，并进入低功耗，唤醒后补偿系统时间。需处理低功耗定时源精度、最大睡眠时间、外设唤醒和调试影响。

### 7.22 FreeRTOS 的临界区与挂起调度器有何区别？【★★★★】

临界区通常屏蔽一定范围中断，保护极短操作；挂起调度器阻止任务切换，但中断仍可能运行，不能保护与 ISR 共享的数据。恢复调度时可能立即发生切换。

### 7.23 `taskYIELD()` 的作用是什么？【★★★】

主动请求调度，让同优先级就绪任务获得机会；它不会使当前任务进入 Blocked，因此如果没有同优先级任务，当前任务可能马上继续运行。

## 8. FreeRTOS 同步与通信

### 8.1 队列、二值信号量、计数信号量、互斥量如何选？【★★★★★】

- 队列：传递有类型的数据副本；
- 二值信号量：事件通知或同步，不表达所有权；
- 计数信号量：累计多个事件或管理同类资源数量；
- 互斥量：保护共享资源，有所有者并支持优先级继承；
- 任务通知：面向单个任务的轻量通知，可表达位、计数或值。

### 8.2 队列传的是指针还是数据？【★★★★★】

FreeRTOS 队列按创建时指定的 item size 复制数据。若队列元素是指针，只复制指针值，必须确保底层对象在接收方使用期间仍有效，并明确缓冲区所有权和释放者。

### 8.3 为什么互斥量不能在 ISR 中使用？【★★★★★】

互斥量有任务所有权和优先级继承语义，而 ISR 不是任务且不能阻塞。ISR 与任务同步应使用队列、二值/计数信号量、任务通知、流缓冲等对应的 `FromISR` API。

### 8.4 什么是优先级反转？如何解决？【★★★★★】

低优先级任务持有锁，高优先级任务等待该锁，中优先级任务不断抢占低优先级任务，导致高优先级任务被间接长期阻塞。互斥量的优先级继承可缓解：临时提升锁持有者优先级，让其尽快释放锁。还可缩短临界区、调整架构或使用优先级上限思想。

### 8.5 什么是死锁？四个必要条件是什么？【★★★★★】

互斥、占有且等待、不可抢占、循环等待。避免方法：统一加锁顺序、一次性申请、设置超时与失败回退、减少嵌套锁、使用消息传递。超时只是让系统能逃脱，不代表状态一定正确。

### 8.6 什么是竞态条件？【★★★★★】

结果依赖多个执行上下文的不可控交错。典型表现是“偶现”。解决前先明确共享状态和不变量，再选择互斥、原子操作、临界区或单所有者消息模型。

### 8.7 任务通知为什么高效？限制是什么？【★★★★】

通知状态直接放在任务控制块中，不需要独立队列对象，内存和执行开销较小。通常是发送方通知指定接收任务，不适合多个接收者竞争同一消息，也不替代需要排队保存多个结构体的队列。

### 8.8 Event Group 适合什么场景？【★★★★】

用多个 bit 表示多个条件或事件，任务可等待任一或全部 bit。它适合状态组合，不携带复杂数据；要注意清零时机、多个等待者语义以及 ISR API 限制。

### 8.9 Stream Buffer 和 Message Buffer 区别？【★★★】

Stream Buffer 传字节流，不保留消息边界；Message Buffer 在其上提供变长消息边界。默认设计通常面向单写者、单读者；多写者或多读者需要外部串行化并核对版本文档。

### 8.10 ISR 唤醒高优先级任务后如何立即切换？【★★★★★】

使用对应 `...FromISR()` API，传入 `xHigherPriorityTaskWoken`；若其变为真，在退出 ISR 前调用端口宏请求上下文切换。变量应按官方示例初始化为 `pdFALSE`。

### 8.11 队列满或空时怎么办？【★★★★★】

任务 API 可设置阻塞超时；ISR API 不能阻塞。系统设计必须定义过载策略：丢最新、丢最旧、覆盖、反压、报警或增大处理能力。仅把队列加大可能只是延后故障。

### 8.12 为什么不建议多个任务直接同时打印日志？【★★★★】

输出会交叉，格式化耗时且串口驱动可能不可重入。可用日志队列交给单独任务发送，定义等级、时间戳和丢弃策略；崩溃路径则准备独立的最小化输出方式。

### 8.13 共享全局变量、队列与消息传递怎样取舍？【★★★★】

简单只读配置可共享；频繁可变状态优先单所有者 + 消息传递，降低锁复杂度；大数据可传指针或零拷贝，但必须建立清晰的缓冲区所有权协议。

### 8.14 二值信号量会累计多次事件吗？【★★★★】

不会，它最多表示一个待处理状态；在被取走前多次 give 可能合并。需要准确累计事件次数时使用计数信号量、队列或任务通知计数，但也要考虑计数上限。

### 8.15 互斥量和递归互斥量区别？【★★★】

普通互斥量被同一任务重复获取可能死锁；递归互斥量允许同一任务多次获取，但必须以相同次数释放。递归锁可能掩盖设计问题，不应滥用。

## 9. 定时器、DMA 与常用外设

### 9.1 DMA 的基本原理是什么？【★★★★★】

DMA 在外设与内存或内存之间搬运数据，减少 CPU 逐字节操作。CPU 负责配置源、目标、方向、长度和触发，DMA 完成或半完成后通过中断通知。

### 9.2 DMA 是否完全不占总线和 CPU？【★★★★】

不是。DMA 会与 CPU/其他总线主设备争用总线；CPU 仍需配置、处理完成事件和缓冲区。高带宽 DMA 可能影响 CPU 访问时延。

### 9.3 DMA 正常模式与循环模式区别？【★★★★】

正常模式传完指定长度停止；循环模式到末尾后自动从头继续，适合 ADC 连续采样和串口连续接收。循环模式必须处理读写指针与覆盖问题。

### 9.4 什么是 DMA 双缓冲/乒乓缓冲？【★★★★】

DMA 填充缓冲 A 时 CPU 处理 B，随后交换，使采集和处理并行。必须确保 CPU 在 DMA 再次写入前处理完成，并正确同步缓冲区所有权。

### 9.5 有 Cache 的 MCU 使用 DMA 要注意什么？【★★★★】

CPU Cache 与 DMA 看到的数据可能不一致。发送前可能要 clean cache，接收后可能要 invalidate；缓冲区按 cache line 对齐并处理长度边界，或放到非缓存区。具体顺序依据芯片和 SDK。

### 9.6 定时器的预分频和自动重装如何计算？【★★★★★】

一般先确认定时器输入时钟，再按芯片公式计算计数频率与周期。常见形式为：

`更新频率 = 定时器时钟 / ((PSC + 1) × (ARR + 1))`

但时钟树中 APB 分频可能导致定时器时钟倍频，必须看参考手册。

### 9.7 PWM 的频率和占空比如何设置？【★★★★★】

频率由定时器时钟、PSC、ARR 决定；占空比由比较寄存器相对 ARR 的比例决定。还要考虑计数模式、极性、分辨率和边界值。

### 9.8 输入捕获和输出比较有什么用途？【★★★】

输入捕获在外部边沿到来时锁存计数值，可测频率、周期、脉宽；输出比较在计数值匹配时产生事件或改变引脚，用于精确定时输出。

### 9.9 ADC 的分辨率、参考电压和采样时间是什么？【★★★★】

理想量化步长与参考电压和位数有关；实际精度还受噪声、参考源、输入阻抗、采样保持时间、布局和校准影响。高阻源需要更长采样时间或运放缓冲。

### 9.10 ADC 数据如何滤波？【★★★】

移动平均、中值、一阶低通、限幅等。选择依据噪声类型、响应速度和计算成本；不能只追求“平滑”，还要分析相位延迟和异常点。

### 9.11 GPIO 上拉、下拉、推挽、开漏分别是什么？【★★★★★】

上拉/下拉为输入提供默认电平；推挽可主动输出高低；开漏只能主动拉低，需要外部或内部上拉，便于线与和电平转换。具体电气限制看数据手册。

### 9.12 按键为什么会抖动？如何消抖？【★★★★】

机械触点在短时间内反复变化。可用 RC/施密特硬件消抖，或软件定时采样、稳定计数、状态机消抖；不要在外部中断里长时间阻塞延时。

## 10. 低功耗与电源管理

### 10.1 MCU 常见低功耗模式有什么区别？【★★★★】

通常从 Sleep 到 Stop/Standby，关闭的时钟和电源域逐渐增多，功耗降低但唤醒延迟增加、保留状态减少。具体名称和行为以芯片手册为准。

### 10.2 进入低功耗前要做哪些事？【★★★★】

确认没有待处理工作；配置唤醒源；处理外设和引脚状态；保存必要上下文；避免浮空输入和外设漏电；处理调试器影响；进入后验证实际电流。

### 10.3 FreeRTOS 下如何做低功耗？【★★★★】

让任务无事时阻塞，利用 Idle/Tickless Idle 进入睡眠；统计下一个到期事件；正确补偿 tick；协调 UART/DMA/定时器等唤醒源。不能仅在 Idle Hook 中随意执行深睡而不检查内核条件。

### 10.4 为什么测得的低功耗电流比手册高？【★★★★★】

常见原因：调试器连接、板载 LED/稳压器/USB 芯片、外设未关时钟、GPIO 浮空或反向供电、传感器未休眠、唤醒过于频繁、测量仪器连接错误。要分离 MCU 与整板功耗。

### 10.5 如何在功耗、响应时间与吞吐量之间权衡？【★★★】

批量处理可以减少唤醒次数但增加延迟；降低频率省动态功耗但任务运行更久；深睡功耗更低但唤醒慢。应根据业务截止时间测量能量，而非只看瞬时电流。

### 10.6 时钟门控和动态调频是什么？【★★】

时钟门控停止不用模块的时钟以减少动态功耗；动态调频/调压根据负载调整性能与能耗。切换时要处理外设时钟、波特率、定时基准和 Flash 等待周期。

## 11. Bootloader、升级与系统启动

### 11.1 Bootloader 的作用是什么？【★★★★★】

完成基础硬件初始化、检查升级条件、接收与验证固件、选择并跳转到应用程序；可支持回滚、版本管理和安全校验。

### 11.2 Bootloader 跳转到 App 前要做什么？【★★★★★】

验证 App 向量表和入口合法；关闭/复位已启用外设与中断；停止 SysTick；清除相关中断挂起；设置向量表偏移；加载 App 初始 MSP；跳转 Reset_Handler。实际还要考虑 Cache、MPU、时钟和 RTOS 状态。

### 11.3 IAP 与 ISP 区别？【★★★】

ISP 常指使用芯片固化的系统 Bootloader 或专用接口在系统编程；IAP 是应用内编程，通过自身软件接收并写入固件。不同厂商术语可能略有差异。

### 11.4 固件升级如何防止断电变砖？【★★★★★】

常用 A/B 双分区或下载区 + 运行区；新固件完整写入并校验后再原子更新启动标志；启动失败计数和看门狗触发回滚；关键元数据采用冗余、版本号和 CRC，并设计断电安全写入顺序。

### 11.5 CRC、哈希、数字签名分别解决什么问题？【★★★★】

CRC 主要检出传输/存储错误，不具备防伪能力；哈希用于完整性摘要，但单独使用不能证明来源；数字签名可验证完整性与发布者身份。加密解决保密性，不能替代签名。

### 11.6 Flash 擦写有什么限制？【★★★★】

通常按页/扇区擦除，写入粒度受限，位一般只能从 1 写为 0，恢复需擦除；擦写次数有限；擦写期间有些器件不能从同一 Bank 取指。参数存储要做磨损均衡、掉电保护和校验。

### 11.7 如何设计参数掉电保存？【★★★★】

记录版本、长度、序号和 CRC；使用双页/日志式追加，写新记录成功后再使其生效；启动时选择最新有效记录；空间满后垃圾回收。不要在每次小变化时立刻擦 Flash。

### 11.8 为什么 App 地址改了还需要改链接脚本？【★★★★】

应用代码必须链接到其实际 Flash 起始位置，向量表和绝对地址才能正确；同时 Bootloader 与 App 的分区、擦写范围和向量表偏移必须一致。

### 11.9 OTA 升级流程如何描述？【★★★★】

检查版本/策略 → 分块下载 → 每块校验与断点续传 → 整包哈希/签名验证 → 标记待试运行 → 重启切换 → 健康确认 → 正式提交；失败则回滚。要说明密钥保护与防降级策略。

## 12. 调试、性能与工程质量

### 12.1 嵌入式常用调试手段有哪些？【★★★★★】

SWD/JTAG 断点与 Watch、串口/RTT 日志、GPIO 打点 + 示波器、逻辑分析仪、总线分析仪、HardFault 寄存器、map/反汇编、静态分析、单元测试和压力测试。面试时要说明不同工具各自解决什么问题。

### 12.2 断点会对实时系统造成什么影响？【★★★★】

暂停 CPU 时外设、看门狗或其他总线节点可能继续运行，导致超时、数据溢出和时序改变；某些调试配置会冻结部分外设。实时问题更适合无侵入日志、追踪或 GPIO 打点。

### 12.3 如何定位“偶现死机”？【★★★★★】

先提高可观测性：复位原因、最后日志、任务状态、栈水位、堆最小值、异常寄存器、看门狗现场；构造高负载和边界条件复现；检查数组越界、竞态、栈溢出、ISR 优先级、DMA 缓冲生命周期和供电干扰。

### 12.4 如何定位内存被踩？【★★★★★】

使用 MPU/数据观察点、缓冲区前后哨兵、栈填充、编译器 sanitizer（在可运行的平台上）、缩小写入范围、检查 DMA 目标和长度；从第一次损坏位置向写入者追踪，而不是只看最终崩溃点。

### 12.5 如何测量一段代码执行时间？【★★★★】

GPIO 前后翻转后用示波器/逻辑分析仪测量；使用 CPU 周期计数器或硬件定时器；多次统计最坏值。日志打时间戳适合较粗测量，但本身有扰动。

### 12.6 优化代码前应该做什么？【★★★★】

先定义指标并测量热点，再优化算法、数据搬运、阻塞与任务架构，最后才是局部指令级优化；同时验证可读性、代码体积、最坏时间和正确性没有退化。

### 12.7 Debug 和 Release 表现不同的常见原因？【★★★★★】

未初始化变量、越界/未定义行为、竞态与时序变化、`volatile` 缺失、栈布局变化、优化消除无副作用循环、断言或日志改变执行时间。不要用关闭优化作为最终修复。

### 12.8 如何设计日志系统？【★★★★】

等级、模块、时间戳、任务/中断上下文、固定格式；异步队列发送；限制格式化和带宽；过载时有丢弃策略；保留崩溃前关键环形日志；发布版可编译裁剪敏感信息和低等级日志。

### 12.9 什么是可重入函数？【★★★★】

函数在尚未完成时可被另一个上下文再次调用且结果仍正确。通常不依赖可变静态/全局状态，或对共享状态有正确同步；不返回共享静态缓冲区。线程安全与可重入相关但不完全等同。

### 12.10 单元测试在嵌入式中怎么做？【★★★】

把纯逻辑与硬件访问分离；通过接口和 fake/mock 替换驱动；在主机上跑大量边界测试，在目标板做集成和硬件在环测试。协议解析、状态机、算法和错误处理最适合先做单测。

### 12.11 代码评审重点看什么？【★★★】

边界和错误路径、资源生命周期、并发访问、ISR 限制、超时、整数溢出、缓冲区长度、返回值、硬件寄存器副作用、日志和可测试性。

### 12.12 什么是 MISRA C？【★★】

面向安全关键/高可靠 C 开发的一组编码规则，减少语言中危险或含糊用法。不是“使用后绝对没有 Bug”，通常配合静态分析、偏差记录、评审和测试。

### 12.13 Git 面试常问什么？【★★★】

工作区/暂存区/提交；branch、merge、rebase 的区别；如何解决冲突；如何撤销但保留历史；如何定位引入 Bug 的提交。项目回答中强调小步提交、清晰信息和评审流程。

### 12.14 编译器告警应该如何处理？【★★★★】

提高告警等级并尽量零告警；理解告警根因，不能用强制类型转换或全局关闭掩盖问题；第三方库告警可隔离管理。重点关注符号转换、截断、未初始化、越界和格式字符串。

## 13. 操作系统与基础算法补充

### 13.1 进程和线程有什么区别？【★★★】

通用 OS 中进程拥有独立地址空间和资源，线程共享进程资源但有各自执行上下文和栈。FreeRTOS 的 task 更接近轻量执行线程，但通常没有进程级虚拟地址空间隔离。

### 13.2 上下文切换为什么有开销？【★★★★】

需要保存/恢复寄存器和调度状态，还会影响 Cache、流水线与时间确定性；任务过多或过度唤醒会增加开销。优化重点常是减少无意义切换和共享竞争。

### 13.3 时间复杂度与空间复杂度是什么？【★★★】

描述输入规模增长时资源消耗的数量级。嵌入式还要关心常数项、最坏情况、内存上限和确定性，平均很快但最坏不可控的算法可能不适合实时路径。

### 13.4 链表与数组如何选择？【★★★★】

数组连续、缓存友好、随机访问 O(1)，但中间插删可能搬移；链表节点分散、插删在已知位置可 O(1)，但查找 O(n)、有指针开销和碎片风险。MCU 中固定数组/对象池通常更可控。

### 13.5 如何实现生产者—消费者模型？【★★★★】

任务间可用有限长度队列；生产者入队，消费者阻塞取队列；设计容量、超时、反压和关停协议。ISR 作为生产者时使用 `FromISR` API，并尽快把工作交给任务。

### 13.6 常见排序和查找算法需要掌握到什么程度？【★★★】

会分析冒泡、插入、快速排序的时间/空间与最坏情况；理解二分查找的前提和边界；能写无溢出的中点及正确循环条件。校招笔试还常考链表、栈、队列、位运算。

## 14. 高频手写题与代码题

### 14.1 反转单链表。【★★★★】

掌握迭代三指针 `prev/current/next`；处理空链表和单节点；能分析 O(n) 时间、O(1) 额外空间。

### 14.2 判断链表是否有环。【★★★】

快慢指针；相遇说明有环。追问可能要求找入环点和计算环长。

### 14.3 实现 `strlen`、`strcpy` 或 `memcpy`。【★★★★】

先澄清接口约束；处理空指针策略、终止符、长度和区域重叠。若要求工程安全版本，要接收目标容量并返回错误。

### 14.4 实现环形队列。【★★★★★】

说明空满判定、索引回绕、容量类型、并发模型；再写入队出队。面试官往往比代码本身更关注边界和线程安全。

### 14.5 实现按位统计 1 的个数。【★★★】

循环执行 `x &= x - 1`，每次清除最低位的一个 1；复杂度与 1 的个数相关。

### 14.6 不用临时变量交换两个数是否值得做？【★★】

异或交换有别名风险且可读性差，加减交换有溢出风险。工程上优先临时变量，面试中应指出技巧的局限。

### 14.7 写一个非阻塞按键消抖状态机。【★★★★】

状态可包含稳定释放、确认按下、稳定按下、确认释放；周期采样并记录时间，不使用长阻塞延时；输出按下、释放、长按等事件。

### 14.8 写一个 UART 帧解析状态机。【★★★★★】

按同步头 → 固定头 → 长度 → 负载 → CRC 解析；每步检查最大长度和超时；错误后能从当前数据中重新同步；输入可能任意分片。

### 14.9 两任务安全访问同一个 I²C/SPI 设备怎么办？【★★★★★】

方案一：互斥量保护完整事务，锁内保持 CS/重复起始等原子语义；方案二：单独总线管理任务 + 请求队列。还要处理超时、优先级反转、设备状态和错误恢复。

### 14.10 设计一个“中断采样、任务处理”的数据通路。【★★★★★】

ISR 只读取必要状态或确认 DMA 缓冲，随后用任务通知/队列唤醒处理任务；处理任务解析、滤波并传给业务任务；明确双缓冲、所有权、队列满策略和最坏吞吐。

## 16. 场景题：面试官更看重思路

### 16.1 串口高速接收时偶尔丢包，你如何排查？【★★★★★】

推荐回答顺序：

1. 量化波特率、包长、到达突发性和丢包位置；
2. 检查物理层和串口错误标志；
3. 检查 ISR 延迟、DMA/环形缓冲、队列是否溢出；
4. 统计各级缓冲高水位和处理耗时；
5. 用 DMA 循环 + IDLE/半满满事件、扩大合理缓冲、批处理或提升消费者能力；
6. 明确定义过载策略并做长时间压力测试。

### 16.2 系统运行几小时后卡死，重启恢复，怎么办？【★★★★★】

记录复位原因与卡死现场；看任务列表、运行时间、栈高水位、堆最小值、锁持有情况和队列状态；排查泄漏、碎片、栈溢出、死锁、计数溢出、tick 回绕、DMA 越界与电源问题；用看门狗恢复但不能以复位代替根因修复。

### 16.3 高优先级任务响应变慢，可能是什么原因？【★★★★★】

长时间关中断/临界区、更高优先级 ISR、等待低优先级持有的资源、优先级反转、调度器被挂起、Cache/总线争用、错误阻塞超时、任务本身执行变长。用时间戳/追踪/GPIO 测量各阶段延迟。

### 16.4 I²C 设备偶发无响应，如何让产品自动恢复？【★★★★】

所有事务设置超时；记录错误类型；先复位 I²C 外设，必要时 GPIO 模式恢复总线和生成 STOP；复位/重上电从机；采用有限次数退避重试；持续失败上报并隔离设备，避免整个系统永久阻塞。

### 16.5 两个任务互相等待导致死锁，如何定位？【★★★★】

记录锁获取/释放和任务状态；查看两个任务阻塞对象及锁所有者；构造锁依赖图；修复为统一锁顺序、减少嵌套或单任务拥有资源；加入超时和诊断，但不要把超时当唯一修复。

### 16.6 采样频率固定，但处理偶尔来不及，如何设计？【★★★★】

硬件定时器触发 ADC + DMA，使用双缓冲；处理任务由半满/满事件唤醒；分析最坏处理时间必须小于缓冲覆盖周期；过载时定义降采样、丢块或报警策略；避免在 ISR 中做算法。

## 19. 回答模板：避免“背过但说不清”

### 概念题

一句定义 → 核心机制 → 使用场景 → 一个限制/坑 → 项目中的例子。

### 对比题

先给结论 → 从实时性、资源、可靠性和复杂度比较 → 根据具体场景选型，不说绝对化答案。

### 排障题

先确认和量化现象 → 分层（硬件/驱动/RTOS/业务） → 提出假设 → 用工具拿证据 → 修复 → 压力与回归验证。

### 项目题

背景与指标 → 自己的职责 → 方案与取舍 → 难点与证据 → 结果数据 → 反思改进。
